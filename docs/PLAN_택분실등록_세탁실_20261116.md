# 택분실 등록 · 세탁실 관리 계획 (2026-11-16, 새 세션 인수용)

이 문서는 사용자와 합의한 **결정 사항과 설계**다. 코드는 아직 없다(0단계 `세탁실` 위치만 운영 DB에 만들어 둠). 새 세션은 AGENTS.md를 읽고 `git fetch`·`git status -sb`부터 한다.

## 1. 왜 하는가

- **택분실**: 택이 떨어진 옷은 바코드를 알 수 없어, 지금은 사무실에서 원래 바코드를 추적하거나 못 찾으면 새로 입고한다. 이 과정이 엑셀 LOST 관리대장·메모에 흩어져 있어 재고조사 때 "미스캔 − 택분실 입고"를 사람이 계산해야 했다.
- **세탁·수선 반출**: 세탁은 택을 떼고 목에 "세탁 라벨(바코드 번호만 적힘)"을 단다. 돌아온 옷의 라벨을 놓쳐 이미 바코드가 있는 옷을 **새로 입고**하는 일이 지하 2층(공동물류)에서 생겼다(2026-11-12 재고조사에서 16벌). 위치 이동 없이 보내서 몇 벌 나갔는지 아무도 몰랐다.

## 2. 확정된 결정

| 주제 | 결정 |
|---|---|
| 세탁·수선 위치 | 한 곳 `세탁실`(창고, 활성). **0단계로 이미 생성.** 보낼 때 이동앱으로 옮긴다 |
| 재고조사 전 | 조사 날짜가 정해지면 세탁실을 비운다(운영 규칙). 조사 쪽 특별 처리는 하지 않는다 |
| 택분실 처리 담당 | 2층 사무실의 **김민지**(수령·바코드 매칭·신규입고 제출과 승인 모두) |
| 신규입고 | 제출·승인 모두 김민지. 가격 참고 표시·신규입고 경고는 **만들지 않는다** |
| 이동 출발 위치 | **그 바코드의 DB 현재 위치**(발견 지점이 아니다). 발견 지점은 따로 저장 |
| 이동 경로 | 매칭할 때 **최종 보관 위치**(온라인 또는 공동물류)를 고르고, DB 위치 → 최종 위치로 **한 번에** 이동 세션을 만든다(사무실 경유 이동 없음) |
| 사진 | 2칸: **칸1 전면(필수)**, **칸2 라벨·로고(선택)**. 신규입고의 물건 사진은 칸1 |
| 수량 대조 | 한 벌씩 사진과 실물 대조. 부족·초과는 거의 없어 규칙을 만들지 않는다(자주 생기면 그때 논의) |
| 사진·실물 연결 장치 | 필요 없음(주 10벌 미만) |
| 검색 | 만들지 않는다. PC에서 통합 물건 조회를 옆 창에 띄워 쓴다 |
| 기한 | 일주일을 넘기지 않는다는 내부 규칙만. 앱은 **7일 초과 표시**(목록 맨 위·홈 숫자)만 한다 |
| 기존 LOST 엑셀 대장 | **이전하지 않는다.** 새 기능은 다음 건부터 시작. 새 기능이 돌면 보고서의 LOST 대장 첨부 기능 제거를 검토한다 |
| 세탁실 완료 방식 | **목록에서 체크**만(번호 입력 방식은 안 만든다). 사진을 보며 체크한다 |
| 세탁실 완료 권한 | 로그인한 직원 누구나(물류팀·김민지). `보낸 위치` 필터로 각자 보낸 옷만 거른다 |

## 3. 전체 흐름

### 3.1 택분실

1. 매장 직원(성수 본점 상주 · 키오스크 순회 직원)이 **체크리스트(`manual/`)에서 "택분실 등록"**: 사진 2칸(칸1 필수) + 메모. 지점은 자동(성수 본점/활성 매장).
2. 상태 `registered`. 키오스크 매장은 물류팀이 신규입고 가는 길에 수량을 보고 가져와 2층에 전달한다(앱 변경 없음). 성수 본점은 직접 2층으로 가져오므로 등록과 동시에 `received`로 처리해도 된다.
3. 김민지가 사무실 PC에서 **대기 목록**(사진 격자, 지점별)을 보고 한 벌씩 실물과 대조 → **수령 확인** → `received`.
4. **찾음**: 사진에서 원래 바코드를 찾아(통합 조회는 별도 창) 입력 + **최종 보관 위치** 선택 → 앱이 `바코드의 DB 위치 → 최종 위치` 이동 세션을 만들고 바코드 재출력 버튼을 띄운다 → 새 택을 붙인다. 상태 `identified`.
5. **못 찾음**: "신규입고" → 입고 위치(공동물류=A, 온라인=U 바코드)·최종 보관 위치·사진(칸1)·브랜드·카테고리·가격 입력 → 입고 세션 자동 생성·제출·김민지 승인 → 기존 흐름대로 엑셀 기록·택 출력. 출처 `택분실`. 상태 `new_entry`("못 찾아 신규입고" 자동 기록).
6. 7일 넘은 `registered/received`는 목록 맨 위에 "7일 초과"로 표시.

### 3.2 세탁실

1. 세탁·수선을 보낼 때 이동앱으로 `세탁실`로 옮긴다(택이 붙어 있어 스캔 가능).
2. **세탁실 현황 화면**: `location='세탁실'`·재고인 물건을 사진(있으면)·보낸 날짜·보낸 위치·경과일과 함께 보여 준다. `보낸 위치` 필터.
3. 돌아온 옷을 **체크 → "세탁·수선 완료"**. 창에서 "바코드 재출력 필요"(기본 켬; 수선만이면 끔)를 고른다.
4. 앱이 보낸 위치별로 **`세탁실 → 보낸 위치` 이동 세션**을 만들고, 재출력 필요 건은 **재출력 대기열**에 올린다.
5. 기존 재출력 화면(`receiving/reprint.html`)에 **"대기열 불러오기"**를 넣어 그날 돌아온 건을 한꺼번에 출력한다. 출력하면 대기열에서 빠진다.

## 4. 데이터 구조(제안)

### lost_tag_items (택분실 등록)

- `id uuid`, `store text`(발견 지점 = `locations.name`), `reported_by text`·`reported_at`
- `photo_front text`·`photo_label text`(비공개 버킷 경로), `note text`
- `status text` check in (`registered`,`received`,`identified`,`new_entry`,`cancelled`)
- `received_by`·`received_at`, `matched_barcode`, `final_location`, `move_session_id`, `new_item_barcode`, `new_session_id`, `resolved_by`·`resolved_at`, `created_at`
- 사진 버킷은 `store-stories`와 같은 방식(등록은 `store_manual_can_use()`, 조회는 매장 업무 사용자 + 관리자)으로 비공개 버킷을 새로 만든다.

### reprint_queue (재출력 대기열)

- `barcode`, `queued_by`, `queued_at`, `printed_at`. 세탁 완료가 넣고 재출력 화면이 비운다.

### 세탁실 "보낸 위치"

별도 컬럼 없이 `move_sessions`·`session_items` 이력에서 그 바코드가 마지막으로 `세탁실`로 갈 때의 출발 위치를 쓴다. 이력이 없으면 화면에서 직접 고르게 한다.

## 5. RPC·권한(제안)

- 등록: `lost_tag_register(store, note, front_path, label_path)` — `store_manual_can_use()`(직원 3 + 관리자 4).
- 수령·매칭·신규입고·취소: 관리자(`is_admin()`). 김민지는 매장 업무 권한(`is_store_staff`/`is_store_manager`)이 **없다**. 등록(매장 업무 권한자)과 처리(관리자)를 서로 다른 권한으로 나눠야 한다.
- `lost_tag_match(id, barcode, final_location)`: 바코드 존재·재고·미매칭 확인 → 이동 세션 생성(출발 = 바코드 DB 위치). 같은 날 제출 순서 문제를 피하려고 **매칭하는 순간 바로 세션을 만든다**.
- `lost_tag_new_entry(...)`: 기존 입고 흐름(`inventory_sessions` → `inventory_hangers` → 물건, `approve_inventory_session`)을 호출하는 방식을 정한다. `receiving/js/index.js`·`session.js`·`hanger.js`의 호출 순서를 먼저 읽을 것. 바코드는 `next_barcode(위치)`(공동물류=`A`+YY+6자리, 온라인=`U`+YYMM+4자리).
- `laundry_complete(barcodes[], need_reprint)`: 재고이고 위치가 `세탁실`인지 확인 → 보낸 위치별 이동 세션 + 대기열. 로그인한 직원 전체.
- 이동 세션은 기존 파이프라인 그대로(22:00 자동 승인 → VM이 DB·엑셀 반영).

## 6. 재고조사와의 연결 (4단계)

재고조사 종합 보고서(`stocktake/results.html` `downloadReport`)가 **택분실 등록 기록**에서 입고 대기·완료를 직접 읽게 한다. 지금은 LOST 엑셀 대장을 첨부(`readLostLedger`)해서 지점별 "택분실 입고(건·금액)"를 센다.

- 분실 추정 차감 대상: 지난 조사 시작~이번 조사 사이 등록된 건 중 취소를 뺀 것(원래 기록이 조사 때 미스캔으로 잡혔을 수 있으므로). 매칭돼 원래 바코드가 이동된 건이 조사 이후라면 차감 여부를 정한다(열린 문제).
- 지점 구분은 `store`(발견 지점)로 한다.
- 이 단계가 끝나면 LOST 대장 첨부 기능을 제거한다.

## 7. 단계

| 단계 | 내용 | 상태 |
|---|---|---|
| 0 | `세탁실` 위치(창고) 생성 | **완료**(2026-11-16, 운영 DB) |
| 1 | 택분실 등록(체크리스트), 대기 목록(수령·7일 초과), 매칭 → 이동 세션, 재출력 연결 | 미착수 |
| 2 | 못 찾은 건의 택분실 신규입고 | 미착수 |
| 3 | 세탁실 현황·완료 버튼·재출력 대기열 | **완료**(2026-11-16, `laundry/`·`scripts/laundry-room-20261116.sql` 운영 DB 적용; 구현 메모는 아래) |
| 4 | 보고서가 등록 기록에서 입고 대기·완료를 읽기, LOST 대장 첨부 제거 | 미착수 |

3단계는 1·2단계와 독립이라 먼저 해도 된다(세탁실 위치가 이미 있다).

3단계 구현 메모(계획과 달라진 점·결정):
- 보낸 위치를 이력으로 알 수 없거나(이력 없음) 지금 쓰지 않는 위치(철수한 매장 등)면 화면의 "돌려보낼 위치"에서 직접 고른다. 서버는 이력의 출발 위치 → 직접 고른 위치 순으로 쓰고 둘 다 없으면 거절한다.
- 22:00(KST) 이후에는 `laundry_complete`가 거절한다(자동 승인이 당일 pending만 승인해 늦게 만든 세션이 조용히 만료되는 것을 막음).
- 재출력 대기열은 `labels.html?barcodes=…`에서 Zebra 직접 출력이 성공했을 때만 비운다. 완료 처리한 물건은 이동 세션이 VM에 반영되기 전까지 세탁실 목록에서 빠진다.

## 8. 열린 문제

- 신규입고 자동 생성을 서버 RPC 하나로 묶을지, 기존 클라이언트 호출 순서를 재사용할지.
- `identified` 건의 보고서 차감 규칙(6절).
- 세탁실 위치가 재고조사 시작 화면의 기본 선택에 포함된다. 비어 있으면 문제없지만, 남은 물건이 있으면 미스캔으로 나온다. 시작 화면에 "세탁실에 아직 N벌" 한 줄 안내를 둘지.
- 등록 취소·수정 권한과 사진 교체.
- 엑셀 쓰기는 기존 VM(`process_inventory`, 2분 크론, Dropbox rev check)이 하므로 새 경로도 같은 길을 탄다. 충돌 시 재시도 동작은 신규입고 승인 코드를 확인할 것.

## 9. 새 세션이 알아야 할 것

- 작업 폴더를 다른 세션과 공유한다. 수정하면 **자주 로컬 커밋**하고 푸시 전에 `git fetch`로 원격 차이를 본다(2026-11-16에 다른 세션이 미커밋 수정을 치워 일부가 사라졌다).
- 운영 DB는 읽기 전용 조회부터. 쓰기는 사전 설명·백업(`~/backups`)·롤백 트랜잭션 테스트 후 적용한다. 공개 저장소이므로 서버 주소·키·PIN을 문서에 쓰지 않는다.
- 이동 세션은 `move_sessions`(`is_correction` true면 정정) → `session_items`. 22:00 자동 승인은 **당일(session_date = 오늘)** 대기 세션만 승인하고, 제출이 늦으면 만료된다.
- 위치 종류는 `locations.kind`(store·warehouse·final·temp)로만 거른다. 위치 이름을 코드에 박지 않는다.
- 공통 UI는 `.miu-*`(`shared/layout.css`), 공유 JS·CSS를 바꾸면 `scripts/bump-cache-version.py`를 돌린다.
- 재고조사 화면·종합 보고서는 `stocktake/results.html`, 처리 상태와 메모 규칙은 AGENTS.md "미확인(missing)"·"종합 보고서" 항목을 본다. 결과 메모가 "분실 아님"/"분실 상쇄"로 시작하면 보고서 계산이 달라진다.
- 주 10벌 미만의 소량 업무다. 알림·검색·번호표 같은 부가 장치는 일부러 뺐다. 늘리지 말 것.
